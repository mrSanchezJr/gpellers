# Контекст проекта Gpellers (ASIS-2AX-V Cross-Platform)

> **Назначение документа:** Этот файл содержит подробное архитектурное и техническое описание проекта `Gpellers-CrossPlatform`. При переносе задачи в новую сессию или чат с искусственным интеллектом передайте данный файл для мгновенного восстановления полного контекста проекта без потери деталей.

---

## 1. Общие сведения о проекте

* **Название программы:** `Gpellers` (внутреннее кодовое имя `ASIS-2AX-V`).
* **Назначение:** Кроссплатформенное графическое приложение оператора для 2-осевого ЧПУ сканирования и управления дозирующей помпой подачи жидкости на базе контроллера **Inectra MSC-3US** (GRBL-совместимого).
* **Стек технологий:** C#, **.NET 8.0**, **Avalonia UI 11.2.0** (Fluent Theme), `System.IO.Ports 8.0.0`.
* **Целевые платформы:** Windows 10/11 (x64), Linux (x64, включая одноплатные компьютеры Raspberry Pi / Orange Pi).
* **GitHub Репозиторий:** [`mrSanchezJr/gpellers`](https://github.com/mrSanchezJr/gpellers).

## 2. Аппаратное взаимодействие и протоколы связи

Программа поддерживает два взаимозаменяемых режима связи через модульную абстракцию интерфейса `ICNCConnection`:

1. **USB Serial COM-порт (`SerialCNCConnection.cs`):**
   * Прямое проводное подключение через виртуальный COM-порт USB.
   * Стандартная скорость обмена: **115200 бод**, 8 бит данных, 1 стоп-бит, без контроля четности.
   * Кроссплатформенная поддержка портов: `COMx` в Windows, `/dev/ttyUSB*` / `/dev/ttyACM*` в Linux.

2. **Беспроводной Wi-Fi TCP (`TcpCNCConnection.cs`):**
   * Прямое сетевое управление по TCP-сокету через аппаратный мост на базе микроконтроллера **ESP-32S (ESP-WROOM-32)**.
   * ESP-32S подключается к аппаратному UART2 контроллера Inectra (GPIO 16 RX2 <-> TX Inectra, GPIO 17 TX2 <-> RX Inectra, общая земля GND, питание 5V).
   * Порт TCP по умолчанию: **`8088`**; резервный IP точки доступа AP: **`192.168.4.1`**.
   * Сокет настроен с флагом `NoDelay = true` для минимизации задержек пакетов.

3. **Автосохранение конфигурации (`ConnectionConfig.cs`):**
   * Все параметры (последний выбранный COM-порт, IP-адрес, TCP-порт, активный режим) автоматически сериализуются в локальный файл `connection_config.json`.

## 3. Графический интерфейс и адаптивность (UI & Scaling)

1. **Векторное масштабирование (`<Viewbox Stretch="Uniform">`):**
   * Все элементы главного окна помещены в единый контейнер `<Viewbox Stretch="Uniform">`. При растягивании или сжатии окна за угол весь интерфейс пропорционально масштабируется без перекрытий, сдвигов и полос прокрутки.
   * `MinWidth="64"` и `MinHeight="40"` предотвращают деформацию сетки.

2. **Безопасный авторазмер окна при старте (`AdjustInitialWindowSize`):**
   * При открытии окна (`OnOpened`) вычисляется реальная рабочая область экрана с учетом системного DPI scaling (`screen.Scaling`).
   * Если базовое разрешение окна (1440x860) превышает 88% видимой рабочей области монитора, размер окна автоматически пропорционально уменьшается, и окно центрируется. Это гарантирует наличие системных рамок для удобного перемещения и изменения размера даже на небольших мониторах оператора.

3. **Экранная клавиатура (Numpad, `NumpadWindow.axaml`):**
   * Независимое немодальное окно цифровой клавиатуры для сенсорных экранов.
   * Поддерживает ввод цифр, точки/запятой, очистку (`C`), шаг назад (`<-`) и подтверждение (`Enter`).
   * Глобальный перехват фокуса (`GotFocusEvent` с `RoutingStrategies.Bubble`) и туннельные клики (`PointerPressedEvent`) автоматически привязывают Numpad ко всем полям ввода и выпадающим спискам (`comboBox1`..`comboBox7`), отображая название активного параметра оператору.

## 4. Выпадающие списки с ручным вводом (`EditableComboBox.cs`)

Все выпадающие списки программы (`comboBox1`..`comboBox7`) позволяют как выбрать значение из выпадающего списка (пресеты), так и свободно напечатать произвольное значение в текстовое поле:

* `comboBox1`: выбор последовательного порта (COMx / /dev/ttyUSB*)
* `comboBox2`: шаг между проходами (0.1, 1, 2 мм)
* `comboBox3`: скорость ручного джога (10, 20, 50, 60 мм/с)
* `comboBox4`: скорость сканирования (50, 100, 200, 400 мм/с)
* `comboBox5`: объём подаваемой воды (1, 10, 50, 100 мл)
* `comboBox6`: время прокачки (10, 20, 100, 200 с)
* `comboBox7`: скорость подачи воды (10, 20, 100, 200 мл/с)

**Техническая реализация:**
* **Архитектура:** `TextBox` + `Border` со значком `▼` + выпадающий `Popup` с `ListBox`.
* **Почему `Border`, а не `Button`:** В Avalonia класс `Button.OnPointerPressed` встроенно перехватывает клик мыши и помечает его `e.Handled = true`, что блокировало раскрытие списка с 1-го нажатия. Использование `Border` с прозрачным фоном устранило проблему: список распахивается **строго с 1-го клика**.
* **Защита синхронизации:** флаг `_isUpdating` предотвращает самозакрытие списка при программной подсветке выбранного пункта во время открытия меню.
* **Закрытие по клику:** клик по любому элементу списка (даже по уже выбранному) закрывает меню.
* **Поддержка Numpad:** свойство `InnerTextBox` позволяет экранной клавиатуре Numpad фокусироваться на поле списка и вводить значения.

## 5. Система версий и обновлений (Single Source of Truth)

1. **Единая точка правды:**
   Версия приложения задается **исключительно в файле `Gpellers.csproj`**:
   ```xml
   <Version>1.0.4</Version>
   <AssemblyVersion>1.0.4.0</AssemblyVersion>
   <FileVersion>1.0.4.0</FileVersion>
   ```

2. **Класс `AppVersion.cs`:**
   * Автоматически считывает версию через `Assembly.GetExecutingAssembly().GetName().Version`.
   * Содержит константы репозитория GitHub: `RepoOwner = "mrSanchezJr"`, `RepoName = "gpellers"`.
   * Формирует строки: `DisplayString` (`"1.0.4"`) и `LabelString` (`"Ver: 1.0.4"`).

3. **Синхронизация с UI:**
   * Правый верхний угол главного окна: `label12.Text = AppVersion.LabelString;`.
   * Окно «О программе» (`AboutWindow`): динамическая строка версии.

4. **Проверка обновлений через GitHub REST API (`UpdateWindow.axaml.cs`):**
   * Запрос к `https://api.github.com/repos/mrSanchezJr/gpellers/releases/latest` с обязательным заголовком `User-Agent`.
   * **Корректная обработка 404:** если на GitHub еще нет опубликованных релизов, программа сообщает оператору: *"Текущая версия: 1.0.4. На GitHub пока нет опубликованных релизов. У вас установлена актуальная сборка"* (без ложной ошибки сети).
   * **Семантическое сравнение (`Version.TryParse`):** отсекает префикс `v` (например, `v1.0.5` -> `1.0.5`) и сравнивает $remote > current$.
   * Выводит оператору changelog релиза («Что нового») и открывает страницу загрузки по кнопке.

## 6. Сборка и автономное развертывание (Self-Contained Single-File)

Программа собирается в полностью автономные исполняемые файлы со **вшитым внутри .NET 8, Avalonia и всеми зависимостями**. Конечным пользователям **не требуется устанавливать .NET**:

* **Скрипт быстрой сборки:** [`build-all.bat`](build-all.bat) (написан на чистом ASCII для исключения сбоев кодировок `cmd.exe`).
* **Профили публикации Visual Studio:**
  * `Properties/PublishProfiles/win-x64-standalone.pubxml` -> `bin/Publish/win-x64/Gpellers.exe` (~89.5 МБ, готовый к запуску Windows .exe).
  * `Properties/PublishProfiles/linux-x64-standalone.pubxml` -> `bin/Publish/linux-x64/Gpellers` (автономный бинарник Linux).
* **Командная строка публикации:**
  ```powershell
  dotnet publish Gpellers.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o bin\Publish\win-x64
  ```

## 7. Логика управления сканером и помпой

* **Управление помпой подачи жидкости:**
  * Прокачка: запуск помпы на заданное время (`comboBox6`).
  * Дозирование: подача заданного объема (`comboBox5`) с заданной скоростью (`comboBox7`).
* **Генерация траектории (`gen()`):** построение растрового плана сканирования (зигзаг) по точкам A и B с заданным шагом и скоростью подачи.
* **Потоковый терминал (`AppendLog`):** вывод логов с кольцевым буфером на 300 строк (`MaxTerminalLines = 300`) для предотвращения утечек памяти.
* **Фильтрация ответов:** автоматическое подавление мусорных ответов `ok`, поступающих на регулярные служебные запросы координат (`?`).
* **Кнопка СТОП / РАЗБЛОК (`button10`):**
  * В нормальном режиме: экстренный останов (байт `!` / `0x85`), переход кнопки в состояние **`РАЗБЛОК.`**.
  * В заблокированном режиме: отправка команды разблокировки контроллера `$X\n` и возврат кнопки в состояние **`СТОП`**.
* **Кнопка ПАУЗА / ПРОДОЛЖИТЬ (`button11`):**
  * Пауза: байт `0x82` (GRBL Feed Hold), надпись меняется на «Продолжить», иконка меняется на Play.
  * Возобновление: символ `~` (GRBL Cycle Start), надпись меняется на «Пауза», иконка меняется на Pause.
* **Поиск нуля (`button15`):** аппаратное базирование по концевикам (`$H`).
* **Обнуление осей (`button14`):** программное обнуление координат.
